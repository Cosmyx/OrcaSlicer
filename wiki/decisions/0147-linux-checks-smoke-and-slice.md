# 0147. Linux: checksums, manifest, smoke run and slice on x64

## Status

Accepted.

## Context

The Linux x64 AppImage can be unpacked and run on a hosted runner. The
aarch64 one cannot run on x64.

## Decision

- Every OS job uploads `cosmyx-checksums-<os>-<tag>` (30 days): its records,
  `SHA256SUMS` of the artifact files and `manifest.json` (path, size and
  SHA-256 of every file of each unpacked app, POSIX paths, sorted).
- x64 AppImage: unpacked, every ELF file must be x86_64; then, when the build
  may be run (0141), `AppRun --help` under `xvfb-run` within 60 s (a hang or a
  crash signal fails, a nonzero exit passes only with a usage text) and a
  slice of the shipped `cosmyx/models/cosmyx_cube.3mf` with
  `--datadir <tmp> --outputdir <tmp> --slice 0` within 300 s: `result.json`
  `return_code` 0 when present, at least one `plate_*.gcode` with
  `; HEADER_BLOCK_START`, `; generated by <SLIC3R_APP_NAME> <SoftFever_VERSION> on`
  (read from the built commit's `version.inc`), `; CONFIG_BLOCK_START`,
  `;TYPE:` and at least 100 `G1` moves.
- aarch64 AppImage: the runtime's ELF machine only; smoke and slice are skipped
  by design. The Linux profile validator: its ELF machine.

## Consequences

- If the bare cube does not slice with default settings, `slice.load_settings`
  in `data/expectations.json` pins a system profile.
- A G-code thumbnail format that drops the header (BTT TFT) would fail the
  slice check.
- Smoke and slice on Windows and macOS, and aarch64 runs on arm runners, are
  deferred.
