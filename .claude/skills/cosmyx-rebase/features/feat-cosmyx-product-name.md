# feat/cosmyx-product-name (PR #103)

## Purpose

The application is named CosmoSlice in every build, while the git tree stays OrcaSlicer. The branding engine renames the
product at build time (window titles, About box, installers, Start menu and desktop shortcuts, macOS menu bar name, Linux and
Flatpak menu entries, hints, the setup guide, and 121 translatable interface texts with their translations in every
language, never marked fuzzy). What must NOT change: the data folder, registry key, executables, bundle id, AppImage and
artifact names (all keyed by `SLIC3R_APP_KEY`, still `OrcaSlicer`), and the G-code header, which still says
"generated by OrcaSlicer" so every tool keeps reading it. A guard reports any new upstream text that names OrcaSlicer;
`just brand-name-candidates` proposes the rows. Commit `1310e1099f` also points the cloud URL fallbacks at CosmoCloud
(companion of `feat/cosmyx-cloud-server`). Decisions 0132, 0133, 0134, 0135, plus 0201 and 0182 (installer identity).

## Intent to preserve

- The product is CosmoSlice wherever a user reads the name; machine-read names stay `OrcaSlicer`: data folder
  (`SetAppName(SLIC3R_APP_KEY)`), `.app`, `.exe`, AppImage names, bundle and Flatpak ids, MSIX identity, ProgID, artifact
  prefix `OrcaSlicer_`, and the G-code producer (`; generated by OrcaSlicer ...`). A CosmoSlice build loads OrcaSlicer G-code and
  OrcaSlicer loads ours.
- Packaging identifiers never change (`PACKAGING_PINS`): a rename of the AppImage desktop `Name=` once broke Linux packaging
  because appimagetool names the file after it.
- Translations stay visible: a renamed msgid keeps its translation with the name replaced (native spellings for zh_CN, zh_TW,
  ko), never `fuzzy`. Inflected languages get exact rows from speakers; never guess a suffix.
- Texts asserted by upstream tests are never renamed; they are allowlisted as `compared`.
- Kept names stay: Orca Cloud, Orca Cube, Orca String Hell, Orca Tolerance Test, Orca YOLO, Orca Arena, Orca Palette, Orca Badge,
  OrcaSliced Combo, Orca Preset Bundle, Orca Filament Library, URLs, file and path names.
- No CosmoSlice name is committed in an upstream-owned file (guard G7). The cloud URL rows must keep pointing at
  `https://orca-cloud.cosmyx3d.fr`.
- If upstream rewrote a patched statement (a macro moved, a literal reworded), do not force the old row: re-derive the row
  from the new code: find the new text with `git grep` for the old symbol, write a counted row with the new exact `old` text,
  keep the same intent (display name to `SLIC3R_APP_NAME`, machine-read to `SLIC3R_APP_KEY`). New visible texts naming
  OrcaSlicer become new `rename.json` rows (a msgid row when it is `_L()`) or allowlist rows with a category reason.
- If upstream already names the product differently (for example a new `SLIC3R_APP_NAME` handling), simplify rows rather than
  stack patches.

## Verification

- `just test-scripts` (workflow `Cosmyx checks`, Ubuntu, macOS, Windows) runs `scripts/cosmyx/tests/test_branding_product_name.py`
  (`RealTreeTest` and `CommittedTablesTest` apply the committed tables to a copy of the real tree; a test fails when a rename
  row's old text appears in a non-Cosmyx `tests/**/*.cpp`), `test_breaker_branding_product_name.py`, and
  `test_branding_guards.py`.
- `just brand-check` runs G1-G8 and writes nothing; G8 is the product-name guard (pre: rows match their counts, inflection rows
  still rename; post: renamed in both places, no confirmed translation names the product, no visible residue outside the
  allowlist, packaging pins intact, app key lines intact). Residue and "needs inflection row" are warnings on development builds
  and errors on release builds.
- `just brand-name-candidates` and `just brand-name-inflections` list rows still missing.
- Catch2 in `tests/cosmyx/test_gcode_header_producer.cpp`, on the branded tree: "The app key that names the G-code producer
  stays OrcaSlicer", "The G-code header names the producer by the app key", "G-code written by this build loads back",
  "G-code written by OrcaSlicer loads", "G-code from another producer is refused" (all `[cosmyx][GCodeHeader]`).
  Upstream plugin host tests (`tests/slic3rutils/test_plugin_host_api.cpp`) must still pass on a branded build.
- Compile the renamed catalogues: `msgfmt --check-format --check-header` on a scratch branded copy.
- Manual: `just brand-apply`, build, check About, window titles, Start menu names, hints, setup guide, a G-code header; then
  `just brand-revert`.
- CI only: `build_all.yml` by `workflow_dispatch` (integration builds also check packaging on all OSes).

## Known pitfalls

- `4199d85961`: the rename row for "OrcaSlicer application is not initialized" rewrote exceptions that upstream plugin host
  tests assert verbatim, failing on every branded build. Row dropped, six literals allowlisted as `compared`, and a script test
  now fails if a rename row's old text appears in a non-Cosmyx test.
- `9af4ed8f4c` (integration build 44545583808): renaming the AppImage desktop entry `Name=` made appimagetool write
  `CosmoSlice-<arch>.AppImage` while the script moves `OrcaSlicer-<arch>.AppImage`, so no AppImage was produced. Row dropped,
  `PACKAGING_PINS` added.
- `adad18b959`: `ConfigBase::load_from_gcode_file` refuses a config block with fewer than 80 keys; the one-key G-code
  fixture made every load fail and one refusal case passed for the wrong reason. The fixture serialises
  `DynamicPrintConfig::full_print_config()`.
- `5582952b19`: Windows CRLF checkouts made raw literals spanning lines carry CR, so rows looked stale (G8); sources are read as
  LF and written back with their own endings.
- `0c61ef1d21` and `e6d245538b`: inflected names (cs, hu, eu, sv), "ORCA SLICER", app-key-derived names (`OrcaSlicer.conf`,
  `.app`, `.AppImage`, Windows folder) and combining marks needed token-rule changes; inflection rows may be phrases.
- `1310e1099f`: cloud URL fallbacks were added to `patches.json` so the web pane falls back to CosmoCloud; counted per row by G8.
- `9c5f42c3bf`: Start menu and desktop shortcut labels and the Flatpak description were named CosmoSlice later; the
  executable label half only (`orca-slicer;CosmoSlice`).
- Decision 0182 (installer identity, `cmake/cosmyx/Packaging.cmake`) owns the Windows install folder, registry key, publisher
  and installer window title; this branch only appends `CPACK_NSIS_DISPLAY_NAME`.
- v2.5.1 pass: adapted with `bbded5e02d`. The real stale set on the tag was 6 msgid rows (AMF load, original names, two plugin-identification rows, presets referring to plugins, body names) plus 1 literal row: the `PythonPluginBridge.cpp` permission docstring, whose DEV text grew the `fs_create`/`fs_delete` paragraphs (DEV `3838002bc8`); it was rewritten to the tag's text. "Objects (%1%) have duplicated connectors" is NOT stale on the tag. The allowlist msgid row absent from the template is not reported by G8. `just brand-name-candidates` proposed nothing after the fix (115 rename rows).
- v2.5.2 pass: although v2.5.2 refreshed every upstream catalogue, `brand-check` gave the same 13 G8 errors (the same 6 msgid rows and the docstring literal row); the v2.5.1 row change applied as is, committed as `e1e7a173f0`; `just brand-name-candidates` proposes nothing.
